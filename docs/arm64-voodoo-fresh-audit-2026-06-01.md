## Candidate Details

### 1. Bilinear Fractional-Index Cleanup

Source block/registers:

- `src/include/86box/vid_voodoo_codegen_arm64.h`, `codegen_texture_fetch()`,
  bilinear path around `ARM64_EMIT_TEX_BILINEAR_SHIFT_SETUP`.
- Current key regs: `w4=tex_s`, `w5=tex_t`, `w6=lod`, `w7=tex_shift`,
  `w10=bilinear_index`, `w16=tex_lod`, `x25=bilinear_lookup`.
- Current shape:

```text
AND w10, w4, #0xf
BFI w10, w5, #4, #4
ASR w4, w4, #4
ASR w5, w5, #4
ADD x11, x25, x10, LSL #5
LDP q16, q17, [x11]
```

Interpreter semantic consumer:

- `src/video/vid_voodoo_render.c`, `voodoo_get_texture()` bilinear path:
  `_ds = s & 0xf`, `dt = t & 0xf`, then `d[0..3]` weight math and
  `tex_read_4()`.

Expected delta:

- Possible `-1` scalar instruction if a baseline ARMv8 form can build
  `((t & 0xf) << 4) | (s & 0xf)` with fewer ops after shifts already needed.
- Possible `code_bytes` decrease only if emitted blocks still carry enough
  bilinear sites. `code_max` may not move.

Required coverage:

- VM validation after build/sign if implemented.
- Clean `mismatch_spans=0`, `fb_mismatches=0`, `aux_mismatches=0`,
  `state_mismatches=0`, `rejects=0`.
- Target counters: nonzero `tmu0_bilinear_pixels` and/or
  `tmu1_bilinear_pixels`.
- JIT metrics: compare `code_bytes`, `code_max`, `compiles`.
- If no static delta appears in generated bytes, reject even if clean.

Reject/defer guard:

- Reject any form that adds temp register pressure, changes coordinate stores
  before `STATE_tex_s`/`STATE_tex_t`, or relies on x86/x86-64 shape.

## Follow-Up Evidence Pass

Date: 2026-06-01
Head: `680c211c2`

Result: no code slice opened.

The bilinear fractional-index block is already at the compact baseline ARMv8
shape for this register contract:

```text
AND w10, w4, #0xf
BFI w10, w5, #4, #4
ASR w4, w4, #4
ASR w5, w5, #4
ADD x11, x25, x10, LSL #5
LDP q16, q17, [x11]
```

`w10` must become `((T & 0xf) << 4) | (S & 0xf)` before the shifted
`bilinear_lookup` address. Baseline ARMv8 has no obvious one-instruction
replacement for the current `AND` + `BFI` pair without changing surrounding
register lifetimes or moving the coordinate shifts. Equivalent forms such as
`UBFX` plus `BFI`, or `AND` plus shifted `ORR`, remain two instructions and do
not improve `code_bytes` or `code_max`.

Reject this slice for now:

- expected static delta: `0`
- expected dynamic win: `0`
- semantic risk: unnecessary, because any change would move around texture
  coordinate state used by interpreter-visible `STATE_tex_s` / `STATE_tex_t`
  validation
- required proof would still need full build/sign and VM validation, but there
  is no codegen win to justify it

Next: no code; need new perf evidence or a different hot block with a proven static instruction delta.

## Implemented Slice: Dither RGB565 Pack Shifted ORR

Date: 2026-06-01

Status: implemented, build/signed, VM-validated.

- `src/include/86box/vid_voodoo_codegen_arm64.h`, dither framebuffer write.
- Added `ARM64_ORR_REG_LSL(d, n, m, sh)`.
- Replaced:

```text

ORR w4, w13, w11
```

```text
ORR w4, w13, w11, LSL #5
```
